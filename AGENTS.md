## Architecture

- **Monorepo**: pnpm workspaces + Turbo (`turbo.json`, `pnpm-workspace.yaml`). The desktop app lives at the project root; reusable packages are under `packages/**` and shared tooling under `tooling/**`.
- **Frontend**: root `src/` — TanStack Start (React + Vite router). See `src/router.tsx` for route setup and `vite.config.ts` for plugins.
- **Desktop shell**: Tauri 2 in root `src-tauri/`. Plugins: `fs` (scope `$HOME` plus `$HOME/**`, declared in the capability so dialog-picked paths stay inside home), `shell` (open), `dialog`, `store`, `log`. Config at `src-tauri/tauri.conf.json`, capabilities at `src-tauri/capabilities/default.json`.
- **Static shell invariant**: Tauri loads `dist/client` as plain static files with no SSR server, so the build must emit a prerendered SPA shell at `dist/client/index.html` carrying the router bootstrap payload (`spa.prerender.outputPath: '/index'` in `vite.config.ts`). A hand-written or hand-generated `index.html` has no bootstrap payload and boots the app to a blank page, so there is deliberately no source `index.html` — the document markup lives in `src/routes/__root.tsx`. Guarded by `src/__tests__/spa-shell.test.ts`.
- **Generated Tauri files**: `src-tauri/gen/**` is regenerated (minified) by the Tauri CLI on every build and is excluded from oxfmt — never hand-format or hand-edit it.
- **macOS packaging**: `scripts/build-mac.sh` is the DMG entrypoint; it removes Tauri's `rw.*.dmg` temporary images, requests both `app,dmg` targets, and asserts both final bundles - an executable `qedit.app`, plus exactly one DMG named for the current `tauri.conf.json` version, so a stale final from an earlier version neither satisfies nor breaks the check. When `QEDIT_ADHOC_SIGN` is set (no Developer ID credentials), it instead builds `app` and `dmg` as separate Tauri invocations with an ad-hoc `codesign --sign -` step in between, so the DMG packages the signed bundle rather than an unsigned one; if the DMG pass removes the app bundle, the script restores it with an app-only bundling pass and signs the final app again before release packaging. Sharp edge: create-dmg's optional Finder-prettifying AppleScript needs a live Finder plus Automation permission, so headless or unattended sessions abort the entire DMG with AppleEvent errors (-1712, -1719). Tauri swallows create-dmg's output and leaves only `error running bundle_dmg.sh`, so the script retries that failure once with `CI=true` (Tauri then passes `--skip-jenkins`) and warns that the DMG ships with **degraded presentation** - valid and mountable, but without custom icon positioning or background. Any other DMG failure fails the retry as well, and the final-bundle assertion still refuses a false success. Covered headlessly by `src/__tests__/mac-packaging.test.ts`, which drives the script against a stubbed `pnpm`.
- **App icons**: `src-tauri/icons/qedit_logo.svg` is the canonical source and the only artwork file kept in the repo. Sharp edge: it is an SVG wrapper around a 1024x1024 base64 PNG, not true vector art, so it cannot be rescaled above 1024px without loss and `src/__tests__/tauri-icon.test.ts` compares the generated icons against that embedded bitmap. Regenerate the full platform set with `pnpm tauri icon src-tauri/icons/qedit_logo.svg -o src-tauri/icons`; `src-tauri/tauri.conf.json` intentionally bundles the generated `icons/icon.png` and `icons/icon.ico` (the latter is the approved source for Windows bundling).
- **Database**: `packages/db` - Drizzle ORM + SQLite schema in `src/schema.ts` (`sessions`, `recent_files`, `recent_projects`), config in `drizzle.config.ts`. Sharp edge: the `db` singleton exported from `src/client.ts` is still an **in-memory** store that only mirrors that schema - nothing is persisted across app restarts yet, and SQLite is not opened anywhere. Recent files/projects are therefore session-scoped; wiring the existing tables to native SQLite is the bounded follow-up.
- **Design tokens**: `src/styles/theme.css` holds the light and dark palettes as `--qedit-*` custom properties keyed on `[data-theme]`, and `@theme` maps every Tailwind token (`--color-*`) onto them. Sharp edge: `--color-*` computes once on `:root`, so JS must read the `--qedit-*` names - `withThemeTokens()` in `src/lib/design-tokens.ts` resolves either palette through a detached probe, which is how Monaco (`src/lib/monaco-setup.ts`) and xterm (`TerminalPanel`) snapshot colors without depending on when the document's `data-theme` is updated.
- **Menu actions**: `src/lib/menu-actions.ts` is the single registry of actions qedit actually performs (shell-handled set plus the Monaco command map). `MENU_DATA` deliberately models the full command surface, so anything absent from the registry renders disabled in both the menu bar and the command palette instead of silently doing nothing. Guarded by `src/__tests__/menu-actions.test.ts`.
- **Theme and preferences**: `src/components/SettingsContext.tsx` owns the `Mode` preference, resolved document theme, and editor/terminal settings. Preferences are stored in Tauri's `qedit-settings.json` store through `src/lib/settings.ts`; the `qedit.settings` localStorage mirror is intentionally kept so `src/routes/__root.tsx` can set the theme before first paint. Monaco theme definitions live in `src/lib/monaco-setup.ts`, and terminal colors are defined alongside `TerminalPanel`. Sharp edge: that no-flash theme script is inlined into `<head>`, so `src-tauri/tauri.conf.json`'s CSP carries `script-src 'self' 'unsafe-inline' blob:` for it - keep this the only inline script and do not widen the allowance further.
- **Terminal**: the integrated terminal is a Rust-owned PTY (`portable-pty`) in `src-tauri/src/lib.rs` exposed as the `terminal_spawn`/`terminal_write`/`terminal_resize`/`terminal_close` commands, driven by an Xterm.js front end in `src/components/TerminalPanel.tsx`. The spawn command must set `TERM=xterm-256color`: GUI-launched Tauri processes do not inherit a terminal type, and interactive shell line editing otherwise redraws cursor/erase sequences incorrectly. Invariants, all covered by the `#[cfg(test)]` tests in `lib.rs`: every session cwd goes through `safe_home_path` (canonicalized and rejected outside `$HOME`), a closed session is deregistered so later writes fail, and `RunEvent::Exit` kills every live shell so no orphan processes survive the app.
- **Terminal tabs**: `TerminalPanel` keeps one mounted Xterm instance and native session per terminal tab, while `src/lib/terminal-tabs.ts` owns active/dirty/running/closed state, ordering, and close fallback behavior. Inactive terminals remain mounted but hidden so their output and shell state survive switching; only the active instance is fit, resized, and focused. Tab rename, drag/drop, keyboard reorder, and terminal-specific shortcuts are frontend/session-scoped. Each bottom terminal session tab (not just a generic "terminal action") can be dragged onto the file tab area to pin that exact session as an editor-area tab, through two parallel mechanisms carrying the same session id: native HTML5 drag-and-drop, where `src/lib/terminal-drag.ts` carries the id in a typed MIME payload plus `text/qedit-terminal` and `text/plain` fallbacks for browsers that only expose the latter, and a pointer-event fallback in `TerminalPanel`'s `TerminalTab` (`onPointerDown` tracks `pointermove`/`pointerup` past a 5px threshold and broadcasts a `qedit:terminal-pointer-drag` window `CustomEvent` with `move`/`drop` phases and client coordinates) that `TabBar` hit-tests against `[data-qedit-terminal-drop-target="true"]` - native DnD alone is unreliable inside the Tauri webview, so both listeners are wired and `onDropTerminal` runs from whichever fires. `TabBar` also exposes a direct "Editor" button next to "Terminal" as a non-drag affordance for pinning the active session. `src/routes/index.tsx` tracks the pinned state as `terminalEditorVisible`/`terminalEditorId`, dispatches `qedit:terminal-select` with the dragged id so `TerminalPanel` selects that exact session, and measures the editor pane's bounds with a live `ResizeObserver` so `TerminalPanel`'s `editorMode` can render it `fixed`-positioned over that pane. This is a pure positioning/visibility toggle on the one mounted panel, so no second PTY session is spawned. Focus Terminal's shortcut is Ctrl+Shift+Backquote (`⌃⇧\``, see `src/lib/shortcuts.ts`), discoverable in the Terminal menu alongside "Open Terminal in Editor Tab" (`terminal.openEditor` in `menu-data.ts`/`menu-actions.ts`).
- **New files**: Cmd/Ctrl+N and File > New File (`file.new`/`new-file` in `menu-actions.ts`) call `EditorContext`'s `createUntitledFile()`, which opens an in-memory `qedit://untitled-N` tab immediately - no dialog, no disk write, no workspace requirement. Naming and location are deferred to Save: `saveActiveFileAs` accepts an optional `defaultPath`, and `routes/index.tsx`'s `saveFile()` passes `${workspaceRoot}/untitled.md` when a workspace is open (else `undefined`, letting the OS dialog choose both folder and filename) whenever `isActiveFileUntitled` is true. `WorkspaceContext.createFile`/`workspace-bridge.ts#createNativeFile` were removed since file creation no longer touches disk before Save. Covered by `src/__tests__/editor-context.test.tsx`.
- **Editor**: Monaco is bundled from the local `monaco-editor` package by root `src/lib/monaco-setup.ts`, which overrides `@monaco-editor/react`'s default CDN loader and wires the Vite `?worker` bundles. Keep it that way — the packaged desktop app must load the editor with no network access. Sharp edge: Monaco token rule `foreground` values must be six-digit RGB hex with no leading `#` - a `--qedit-*` custom property that resolves to a named CSS color (e.g. `green`) throws `Illegal value for token color`, so theme rule colors go through `toMonacoTokenColor()` in `src/lib/monaco-colors.ts`, which falls back to the token's declared fallback hex (or `000000`) instead of passing the named color through. Covered by `src/__tests__/monaco-colors.test.ts`.
- **Workspace mutations and search**: native rename/delete/Save/Save As operations are centralized in `src/lib/workspace-bridge.ts` (see "New files" above for file creation, which is untitled-buffer-first and no longer part of this bridge); `WorkspaceContext` handles `qedit:workspace-refresh` so the Explorer invalidates immediately after disk changes. Quick Open scans visible workspace files on demand, while the tree remains lazy for browsing. The status bar's git branch also comes from there (`readGitBranch`) through the Rust `git_branch` command, which shells out to `git branch --show-current` behind the same `safe_home_path` boundary as the terminal and reports no branch (rather than an error) whenever git fails or HEAD is detached. Opening a folder or a recent workspace (`openFolderDialog`/`openRecentProject` in `WorkspaceContext`) dispatches a `qedit:open-sidebar` window event after `loadWorkspace` succeeds; `src/routes/index.tsx` listens for it to force the left Explorer sidebar open. As a second, more general guarantee, `src/routes/index.tsx` also tracks `workspaceRoot` directly and reopens the sidebar whenever `src/lib/workspace-sidebar.ts`'s `shouldOpenSidebarForWorkspace` sees it change to a new non-null value; the user's own close action is unaffected since neither mechanism re-fires while `workspaceRoot` stays the same. Covered by `src/__tests__/workspace-context.test.tsx` and `src/__tests__/workspace-sidebar.test.ts`.
- **Markdown**: `.md` files use the local React-node renderer in `src/lib/markdown.tsx`; it intentionally supports a small safe subset and only enables `http(s)` and `mailto` links. Monaco remains the editing fallback through the Edit/Preview toggle in `src/components/Editor.tsx`.
- **Diagnostics**: `src/lib/app-logging.ts` wraps `tauri-plugin-log` (registered with the native `LogDir` target in `src-tauri/src/lib.rs`) for local-only logging - folder picker attempts/results/errors and terminal tab create/activate/close/drag/drop events. No network telemetry; `Help > Open Local Logs Folder` (`help.openLogs` in `menu-data.ts`) opens the log directory via the `shell` plugin. Keep new diagnostics local-only through this module rather than adding other log sinks.
- **UI library**: `packages/ui` — shadcn components (Tailwind v4) plus `cn()` utility.
- **Shared**: `packages/shared` — `cn` utility, event emitter context, registry pattern, mode utils.
- **Tooling**: `tooling/typescript` — shared `base.json` tsconfig.
- **Marketing website**: `website/` — standalone `@qedit/website` Vite + React static app (own `package.json`, not part of the desktop app's dependency graph), added to `pnpm-workspace.yaml` as its own package. No SSR, backend, or API; external links and release metadata are centralized in `website/src/content.ts`. Deployed to GitHub Pages by `.github/workflows/website.yml` on pushes to `main` touching `website/**`, using the official `actions/configure-pages` + `actions/deploy-pages` flow with `VITE_BASE_PATH=/qedit/` (see `website/vite.config.ts` for the base-path fallback and `website/README.md` for retargeting to `qedit.github.io` or a custom domain).

## Commands

| Command | Scope |
|---|---|
| `pnpm install` | Install all workspace deps |
| `pnpm run dev` | Start the root Vite development server |
| `pnpm run tauri:dev` | Start the Tauri desktop development shell (which starts Vite) |
| `pnpm run lint` | oxlint across workspace |
| `pnpm run lint:shell` | shellcheck over `scripts/*.sh`; skips with a notice when shellcheck is absent unless `QEDIT_REQUIRE_SHELLCHECK=1` |
| `pnpm run format` | oxfmt --check |
| `pnpm run format:fix` | oxfmt auto-fix |
| `pnpm run typecheck` | Root tsc plus package typechecks via Turbo |
| `pnpm run test` | Root Vitest plus package tests via Turbo |
| `pnpm run build` | Root Vite production build |
| `pnpm run website:build` | Build the `website/` marketing site (`pnpm --filter @qedit/website build`) |
| `pnpm run build:native` | Full Tauri desktop build (Rust + frontend) |
| `pnpm run db:generate` | drizzle-kit generate migrations |

### Check & verify pipeline

| Command | Scope |
|---|---|
| `pnpm run check` | Fast CI — lint, format, typecheck, web tests, Rust tests, Vite build, + Rust compilation check |
| `pnpm run check:native` | Rust-only: `cargo check` on the Tauri workspace (catches broken plugin configs, JSON errors, compilation failures without a full build) |
| `pnpm run test:native` | Rust unit tests (terminal/PTY behaviour) via `cargo test`. Spawns real shells through the `tauri` `test` feature; part of `pnpm run check` |
| `pnpm run build:native` | Full Tauri native build (app bundle only, no DMG/installer) |
| `pnpm run smoke:native` | `scripts/native-smoke.sh` — launches the built app, fails if it exits during startup or ignores SIGTERM. On macOS it launches the packaged `.app` and asserts the embedded `qedit.icns` matches the current artwork |
| `pnpm run verify` | Full pipeline: `check` + `build:native` + `smoke:native` |
| `pnpm run build:mac` | `scripts/build-mac.sh` - DMG release bundle. Sharp edge: it builds `app,dmg` because the dmg-only target deletes `qedit.app` as an intermediate; `CI=true` is set only on the retry after the Finder presentation step fails (see the macOS packaging note above) |
| `pnpm run build:all` | Host bundle only (`scripts/build-all.sh`): Tauri cannot cross-build complete bundles, so CI must run it once per platform runner |
| `pnpm run release <version>` | `scripts/release.sh` — refuses unless the version matches `package.json`, `tauri.conf.json`, and `Cargo.toml`; set `DRY_RUN=1` to stop before tagging |

Release matrix: `scripts/release-build.sh` only accepts a native Rust host triple for each target (`macos-{arm64,x64}`, `windows-{arm64,x64}`, `linux-{arm64,x64}`), then writes deterministic artifacts below `dist/release/v<version>/<target>`. Linux AppImage bundling uses the `bundle.linux.appimage.files` mapping in `src-tauri/tauri.conf.json` to provide the shell plugin's opener without requiring host `xdg-utils`; the command also sets explicit CI/headless environment variables. `scripts/release-sign-prepare.sh` installs the macOS identity before Tauri creates the DMG only when the complete signing credential set is present; otherwise `scripts/build-mac.sh` builds the app separately, ad-hoc signs it, and creates the DMG from that signed bundle (the workflow records an unsigned, not-notarized public preview, or fails closed under `QEDIT_REQUIRE_SIGNING=1`). Sharp edge: Tauri invokes codesign during macOS bundling whenever `APPLE_SIGNING_IDENTITY` is set, even to an empty string, so `.github/workflows/release.yml` splits the "Build native bundle" step into a signed macOS branch (sets `APPLE_SIGNING_IDENTITY` from the secret), an unsigned macOS preview branch (no `env:` block at all), and a non-macOS branch, gated on `steps.macos-signing.outputs.enabled`. `scripts/release-sign.sh` records signed/unsigned status, and `QEDIT_REQUIRE_SIGNING=1` makes missing credentials release-blocking. `scripts/release-verify.sh all` refuses incomplete or stale matrices, requires matching per-target signing metadata, and emits `SHA256SUMS` plus deterministic provenance. The authoritative hosted-runner matrix and publish flow are `.github/workflows/release.yml`; local publication uses `scripts/release.sh` and `gh-axi`. Sharp edge: the workflow's "Ensure release branch and tag" step sets a local (`git config --local`, never `--global`) automation identity before creating the annotated release tag, since the runner has no git identity configured by default; it also checks for an existing release branch/tag ref before pushing/tagging so manual-dispatch reruns after a partial publish are safe.

## Constraints

- TypeScript strict mode throughout (`strict: true`, `noUnusedLocals`, `noUnusedParameters`).
- `verbatimModuleSyntax: true` — use `import type` for type-only imports.
- ESM (`"type": "module"`).
- No Supabase, Stripe, auth, or SaaS code. This is a file editor.
- Tauri fs scope limited to `$HOME` and `$HOME/**`. No network permissions beyond localhost.
